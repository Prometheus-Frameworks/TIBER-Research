### Provider-state contribution

The R2 packet/trace family must be able to represent all of these without narrative repair:

- historical governed production/basic usage is available while current 2026 usage is unavailable;
- a weekly Forecast contract/runtime is implemented while a current governed forecast artifact is unavailable;
- FFC market observations are real but stale and separately rights-gated for refresh/public delivery;
- an operator-seeded Teamstate row is inspectable but not source-backed Shared Reality;
- a candidate Ledger record is append-only operator evidence, not promotion;
- platform player status, official NFL designation and fantasy reserve eligibility are different claims;
- exact canonical identity may be unresolved even when a provider display name is present.

A packet status cannot be inferred from file location, schema validity, route existence, generation time, or successful model execution. Each claim needs its own evidence clock, authority, source/asserter, transformation lineage, rights state and coverage.

### Mandatory public/private isolation fixture

Add or bind an offline fixture in which:

1. a public roster packet for synthetic user A compiles successfully;
2. private Management context exists for synthetic operator B;
3. the caller changes display strings, roster IDs, league IDs, workspace IDs and a caller-supplied `user_id`;
4. no B context, existence signal, cached value, log body, precedent, operator thesis or mutation becomes visible;
5. state-backed operations reject the unauthenticated caller before resource lookup;
6. the public roster compiler continues to work with the private subsystem disabled.

Deterministic failure conditions:

- a caller-provided principal selects database state;
- a public UI route is mistaken for authorization;
- another workspace's existence is distinguishable;
- an anonymous read or write reaches operator state;
- a request/response cache is not scoped to the authenticated principal;
- a private API body is copied into ordinary request logs;
- a local-stdio safety assumption is generalized into remote/multi-user safety.

### R2 placement implication

Research should keep this as a transport-independent behavior/threat fixture. The eventual application owner must enforce principal/resource scope; MCP/HTTP adapters must not invent it. A remote transport cannot be evaluated honestly until the local application operation passes the same fixture without relying on GitHub, provider memory or a hidden default operator.

No production vulnerability was probed and no private data was read. The finding is static code-path evidence with `production_binding_unknown`.
